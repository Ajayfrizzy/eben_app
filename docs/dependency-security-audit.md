## Dependency changes and justification

- Expo 54.0.36 → 54.0.37 and expo-constants 18.0.13 → 18.0.14: Doctor-recommended compatible patches. Expo remains SDK 54, React Native remains 0.81.5, and React remains 19.1.0.
- Vitest 2.1.9 → 4.1.11: deliberate development-tool major upgrade to remove critical Vitest/Tinypool and mocker/Vite/esbuild advisories. This changes no application architecture. The default `vitest run` interface and all 43 tests pass. Vitest's new dependency tree uses Vite 8.3.4; Tinypool and the old esbuild/Vite stack are removed. No UI or browser test server is enabled.
- Targeted compatible refreshes include shell-quote 1.10.0 → 1.12.0; brace-expansion branches 1.1.21/2.1.7/5.0.12; xmldom 0.8.15/0.9.12; js-yaml 3.15.2/4.3.2; fast-uri 3.1.8; nanoid 3.3.20; source-map-js 1.2.2; compression 1.8.2; tar 7.5.22; undici 6.29.0; browserslist 4.29.3; baseline-browser-mapping 2.11.28. Associated compatible Babel/browser-data packages were resolved by npm.
- Scoped root override `@expo/metro-config → postcss ^8.5.29`: Metro's `~8.4.32` range otherwise retains vulnerable 8.4.49. This stays on PostCSS major 8 and removes the CSS/source-map advisories. Android export and Doctor validate the integration; it does not establish web CSS behavior. Reassess/remove this override when the SDK's supported range includes a patched version.
- Broad `npm audit fix` failed with peer resolution errors rather than yielding a safe update. Targeted installs/updates were used instead. npm 10.8.2 crashed while resolving the Vitest upgrade; npm 11.13.0 under Node 22 generated the update. A final clean install and quality checks succeeded with Node 22.23.3/npm 10.8.2, matching the repository's declared npm version.

## Risk classification and unresolved root advisories

`npm --omit=dev` is not an Android bundle inventory: Expo and React Native declare CLI, Metro, signing, and Jest packages as production dependencies. These inherited findings primarily concern the developer/build machine. Android runtime relevance is classified by dependency use, not the lockfile flag alone. This review does not prove absence of every reachable exploit.

| Dependency / severity           | Exploit precondition and relevance                                                                                                                                                              | Why retained / action                                                                                                                                                                                                                             |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| decode-uri-component / moderate | Malformed percent-encoded deep-link/query input can cause excessive decoding work. Used through query-string and React Navigation/Expo Router; relevant to Android runtime before route guards. | Patched 0.5.0 is ESM-only, while query-string 7 requires CommonJS `^0.2.2`. Do not force a breaking override. Needs a tested upstream router-compatible fix/backport; keep this as a release security blocker. Route gates do not fix parser DoS. |
| braces / high                   | Deeply nested attacker-controlled glob patterns exhaust stack in Metro/Jest tooling. Most inputs here come from the repository/configuration.                                                   | Latest published version 3.0.3 remains affected; no compatible patched release found. Review contributed assets before building.              |

Current path is xcode project tooling; limited Android relevance.                                              | xcode depends on UUID 7; fixed versions start at 11.1.1. Avoid a multi-major override without upstream compatibility work. No affected buffer API call demonstrated in this app.                                                                  |

Remaining direct packages reported by npm: `@sentry/react-native`, `expo`, `expo-constants`, `expo-linking`, `expo-notifications`, `expo-router`, and `react-native`. Except for the navigation decoder path, their listed advisories are propagated tooling findings. Upgrading those SDK packages to unrelated major versions is outside the safe SDK 54 patch scope.

- [sprintf-js vulnerable to denial of service through unbounded precision specifiers](https://github.com/advisories/GHSA-hp3w-g68c-fv3c) — `sprintf-js`, affected `<=1.1.3`.
- [uuid: Missing buffer bounds check in v3/v5/v6 when buf is provided](https://github.com/advisories/GHSA-w5hq-g745-h8pq) — `uuid`, affected `<11.1.1`.

## Operational limits

- No production Supabase resources, migrations, or remote accounts were accessed or modified.
- Physical Android, native APK installation, live email/auth, and RLS integration remain unexecuted. See the [Android checklist](manual-test-checklist.md) and [isolated RLS plan](rls-integration-test-plan.md).
- The release route gate prevents fixture-backed student experiences even after successful authentication. It intentionally blocks those routes until live implementations are reviewed; the app is not ready for production release.
- `.DS_Store` is covered by the existing ignore rule. Previously tracked root/app metadata files are removed from the index while their local bytes are preserved.
