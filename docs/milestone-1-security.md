## Android URL-decoder investigation

`expo-router`/React Navigation → `query-string@7.1.3` → `decode-uri-component@0.2.2` remains release-relevant. Its malformed UTF-8 fallback repeatedly splits/decodes percent sequences and can cause excessive CPU/stack work. Fixed 0.5.0 is ESM-only; the SDK 54 query-string consumer is CommonJS and declares `^0.2.2`. A forced override would change module semantics and has not been justified.

Added `apps/app/+native-intent.ts` and a tested native intent sanitizer to reject external paths over 8192 characters or paths that fail native `decodeURIComponent` validation before Expo Router's legacy decoder. Recovery parsing separately bounds input and uses the built-in URL parser. This protects these native entry paths but does **not** prove every web/internal/dependency entry path safe or remove GHSA-vcc3-ghjq-m6fr. Keep the advisory open and require a reviewed compatible upstream fix/backport (and device malicious-link testing) before release. No fabricated clean audit claim.
